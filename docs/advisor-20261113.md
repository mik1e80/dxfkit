# 2026-11-13 顾问建议核对与修改

后续补充：[FreeCAD原生R12导出](../examples/cad-r12/README.md)已实际完成，三份输出均为AC1009，两个正常案例及一个应报警反例。下文“真实R12导出待补充”保留本轮最初核对时的状态；目前仍未覆盖不同CAD来源、非默认OCS或MINSERT的原生导出，不能把这三份文件扩大为完整认证。

以main的`d3e8000`为基线核对最近一次意见。顾问关于“没有ReadLimits、候选预算、SECURITY或安全测试”的描述已落后于11月8日提交；现有实现和定向证据见[安全整改](security-20261107.md)，本轮不重复实现或把旧意见当新缺陷。

## 本轮补齐

- [47文件来源清单](../testdata/ezdxf/MANIFEST.json)：源仓库/路径、本地SHA-256、MIT、首次收录提交及其作者日期。历史上游commit/blob无法确认，保持null；首次收录日期不冒充上游创建日期。
- [六模型来源清单](../examples/r12-validation/provenance.json)与[许可说明](../examples/r12-validation/LICENSE.md)：项目自建、生成器、验证器、设计参数、实例数、原始字节哈希及Apache-2.0。第三方阵列语料保持MIT，actual数据不冒充设计真值。
- 旧代码页边界与公开API回归：AC1009/ANSI_936按Latin-1降级，原始字节保持且诊断传到检查报告；AC1021仍优先UTF-8。没有增加GBK映射表，也不声称已支持中文R12文本兼容。首次1024字节外的声明仍可能无法探测。
- 文档校验门禁逐文件核对两个manifest的数量、唯一性、路径集合、许可与SHA-256，防止来源表随文件变化而过期。

## 仍然未完成的建议

当前读取层保留预算范围内的记录，不是全部R12字段/引用/实体语义认证。SHAPE、VIEWPORT、字形、DIMENSION和关联属性完整布局仍见[能力矩阵](capabilities.json)，本轮未扩大实体支持。

既有三份CAD导出仅证明相应导出器路径可读取；FreeCAD为AC1014，OpenSCAD缺版本声明，不能证明真实CAD的AC1009兼容。真正由CAD应用直接导出的2～3份R12及其独立真值仍待补充；不能把自写文件、改版本字符串或ezdxf转存当作该项完成。

本次遵循参赛者此前“只做必要轻量测试”的要求，不执行顾问建议的full CI，不创建最终标签、不发布0.2.0，也不修改报名表或Gitlink。定向CI与完整验收的区别继续公开保留。旧代码页可插拔解码/GBK实现、真实R12 CAD导出和最终完整验收仍是明确待办，不把文档修改当能力完成。
