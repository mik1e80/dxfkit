# 固定线段输入的运行成本

在固定 SDK 下运行 `moon run examples/performance --target wasm --release --deny-warn`。输入线段为 `(2n,0) → (2n+1,0)`，计时前生成源字节。读取含扫描与结构构建，检查和 SVG 各自包含一次展开。

| 线段数 | 输入字节 | 读取 ms | 展开 ms | 检查 ms | SVG ms | 放置 | 检查不完整 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1,000 | 31,926 | 20 | 8 | 9 | 9 | 1,000 | 否 |
| 10,000 | 338,926 | 125 | 51 | 62 | 65 | 10,000 | 否 |
| 100,000 | 3,588,926 | 1,133 | 267 | 268 | 293 | 10,000 | 是 |

以上为 Windows 上固定 SDK 0.10.14、Wasm release 单次观测。10 万线段触发展开限额，耗时对应部分结果。样例未测峰值内存或密集相交数据，计时不作为 CI 阈值。

Linux 定向 CI 在独立 Native 进程重放同一输入，使用 1 GiB 虚拟内存额度及 45 秒运行上限。日志中的 `peak_rss_kib` 是该进程的实测峰值常驻集，适用于这组输入和运行环境。
