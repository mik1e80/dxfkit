# 十类模型：输入、测试数据与总结

[结果总表](SUMMARY.md) · [实际 CLI 模型总览](OVERVIEW.svg) · [已知设计尺寸](expected.json) · [实际断言与数值](results.json)

这些是按参赛者提供的十类模型清单新建的 **10 个参数化 ASCII DXF 自建模型**，单位声明为毫米。不是用户上传的现成 CAD 文件，也不是新增的第三方语料。设计坐标和解析公式先在 `generate-models.cjs` 中定义，被测输出由独立的公开接口调用包和实际 CLI 获取；不从生产离散器反推预期。

| 模型 | 人工指定的设计真值 | 核对项目 |
| --- | --- | --- |
| 01 简单矩形板 | 100×60，四个顶点、面积 6000 | 解码字段、包围盒、闭合、四条边、面积、正常无告警 |
| 02 四孔板 | 100×60，四孔 Φ6；孔心 (10,10)/(90,10)/(90,50)/(10,50) | 圆心、半径、全部孔心间距、轮廓；外框净距解析值 7，阈值 0.5/8 的不报警/报警对照 |
| 03 圆弧零件 | R20：中心 (30,30)，300°→60°；R10：中心 (80,30)，90°→270° | 逆时针方向、半径、端点、包围盒和解析曲线采样距离 |
| 04 椭圆 | 中心 (10,20)，相对长轴 (10,0)，轴比 0.5；长短轴全长 20/10 | 圆心、轴向量、尺寸、精确包围盒、椭圆方程和解析误差 |
| 05 bulge 多段线 | (0,0)→(20,0)，bulge=-1，再接 (20,-10) | 上半圆方向、端点、bulge 字段、包围盒 [0,20]×[-10,10]、解析误差 |
| 06 spline | 三次钳制样条，控制点 (0,0)/(0,40)/(80,-40)/(80,0) | 次数、节点、控制点、端点，与独立 Bernstein 曲线采样对照 |
| 07 BLOCK/INSERT | 同一 10×4 块，基点 (1,2)，三次不同旋转/非均匀缩放/平移 | 每个世界顶点、闭合、尺寸与图层 0 继承；不是 INSERT 阵列支持 |
| 08 多图层图 | CUT、TEXT、AUX-OFF、AUX-FROZEN；关闭/冻结层各一条开放线 | CUT 轮廓闭合、图层身份、文字覆盖提示、两种图层状态提示和闭合检查筛选 |
| 09 有意错误 | 一处 0.1 的开口、一对长度 10 的重复线 | 正确发现闭合和重复问题，没有自交/退化或覆盖缺失误报 |
| 10 覆盖边界 | 正常矩形、HATCH、非默认 OCS 圆 | 正常部分保留，明确 HATCH 与 OCS 限制、检查不完整、strict 失败 |

`models/` 为 DXF；`references/` 为独立公式生成的 CSV 和 SVG；`actual/` 为真实报告、真实 SVG 和公开库接口原始数据。所有模型的普通几何输入都通过 `Drawing::entities()`、`Entity::bounds()`、`Drawing::expand()` 获取实际值，另将真实 CLI SVG 点列逐点与库接口比较，防止预览掩盖数据路径差异。

## 运行与更新

在仓库根目录、固定 MoonBit 工具链下执行：

```sh
node examples/model-validation/generate-models.cjs
node examples/model-validation/verify.cjs
```

这是 10 个模型的针对性测试，不自动运行全量测试。生成器默认只比较设计文件；验证器默认实际运行模型并与保存值比较，差异会失败。仅在人工检查差异后使用相应脚本的 `--write` 重建输入或更新实际记录，CI 不使用 `--write`。

几何字段/坐标绝对误差 ≤1e-9；曲线取 2049 个解析点，核对参考点到输出折线及输出顶点到参考采样折线的双向距离，阈值为 0.002+1e-9。度量在 JSON 中保留 12 位有效数字用于展示，断言使用未舍入数值。有限采样不是所有曲线的连续误差证明。输入 SHA-256 规范化为 LF，原始公共接口数据和 SVG 不改写数值。

## 外部确认边界

05 的几何预期由 bulge 的解析半圆定义确认，**未进行 CAD 软件目视确认**。06 的 CSV/SVG 是独立 Bernstein 公式参考，**不是外部 CAD 软件导出**，未声称已完成外部导出对照。这两项如需形成外部 CAD 证据，应补充软件名/版本、导出文件和人工确认记录；当前测试不冒充这些证据。

模型 03/05/06 故意为开放曲线，会有预期闭合警告；08 含未转字形轮廓的文字，10 含覆盖限制，严格模式退出 1 是预期结果。只有“实际与预期一致”才计为模型测试通过，不能把 strict=0 当成所有模型的目标。

最终交付标签统一为 `submission-0.1.1-20261022-r2`。`_build/model-validation.json` 保存每次运行的实际 HEAD、dirty 状态和工具版本；完整 CI 通过后随同提交的 Pages 复制为 `model-validation-verification.json`。本目录数据与现有 47 文件回归分开；第三方逐图纸独立几何真值仍为 0/47。
